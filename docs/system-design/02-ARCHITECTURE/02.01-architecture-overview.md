## 1. Tổng quan

vnbroker sử dụng kiến trúc **hai tầng** (Two-Tier Architecture):

- **Tier 1:** Dữ liệu thị trường ẩn danh, người dùng không cần biết provider
- **Tier 2:** Dữ liệu cá nhân hóa, bắt buộc chọn provider tường minh

## 2. Sơ đồ kiến trúc

```
┌─────────────────────────────────────────────────────────────┐
│                    NGƯỜI DÙNG                                │
│   Market(auto=True).bulk.history(symbols=[...])             │
└─────────────────────────┬───────────────────────────────────┘
                          │
┌─────────────────────────▼───────────────────────────────────┐
│              TIER 1 DATA ENGINE                             │
│  ┌─────────────┐  ┌──────────────┐  ┌───────────────────┐  │
│  │ Bulk Router │→ │ Health Router│→ │ Provider Pool     │  │
│  │ (chia tải)  │  │ (sức khoẻ)   │  │ (auth + no-auth)  │  │
│  └─────────────┘  └──────────────┘  └───────────────────┘  │
│         │                                    │              │
│         ▼                                    ▼              │
│  ┌─────────────┐                    ┌───────────────────┐  │
│  │ Normalizer  │                    │ Connection Pool   │  │
```

## 3. Các thành phần chính

### 3.1 Bulk Router (`vnbroker/core/bulk_router.py`)

Chia tải bulk trên nhiều provider dựa trên sức khoẻ:

- Round-robin distribution
- ThreadPoolExecutor cho concurrency
- Graceful per-provider error handling

### 3.2 Health Router (`vnbroker/core/health_router.py`)

Theo dõi sức khoẻ provider theo thời gian thực:

- Rolling latency window (deque maxlen=50)
- Delegate sang `source_router` cho failure/success
- Sort providers theo average latency

### 3.3 Provider Pool (`vnbroker/core/provider_pool.py`)

Quản lý tất cả providers, bao gồm auth providers:

- Auto-detect DNSE/SSI/TCBS từ env
- Module filtering (mỗi provider support khác nhau)
- Graceful degradation khi auth providers không có

### 3.4 Connection Pool (`vnbroker/core/utils/connection_pool.py`)

Session dùng chung cho mọi thread:

- Singleton pattern với double-checked locking
- `HTTPAdapter(pool_connections=256, pool_maxsize=256)`
- Thread-safe (requests.Session)

### 3.5 Normalizer (`vnbroker/core/utils/normalizer.py`)

Chuẩn hoá kết quả từ mọi provider:

- tz-aware `Asia/Ho_Chi_Minh`
- Boundary filter (start/end)
- Sort + reset index
- Xử lý cả DataFrame và list[DataFrame]

## 4. Luồng dữ liệu

```
User Request
    │
    ▼
BulkRouter.fetch_history(symbols, start, end)
    │
    ├──→ HealthRouter.get_healthy_providers("quote")
    │         │
    │         └──→ ["vci", "kbs"]
    │
    ├──→ Distribute symbols (round-robin)
    │         │
    │         ├──→ vci: ["ACB", "VNM", ...]
    │         └──→ kbs: ["HPG", "VCB", ...]
    │
    ├──→ ThreadPoolExecutor (concurrent fetch)
    │         │
    │         ├──→ VCI.fetch_multiple(...)
    │         └──→ KBS.fetch_multiple(...)
    │
    ├──→ Merge results
    │
    ▼
Normalizer.normalize_history(result, start, end)
    │
    ▼
DataFrame (tz-aware, sorted, with symbol column)
```

## 5. Failover mechanism

```
Provider A (VCI)
    │
    ├──→ Request → Success → record_success()
    │
    ├──→ Request → 429 Error → record_failure()
    │         │
    │         └──→ Health store: failures=1, cooldown=5s
    │
    ├──→ Request → 429 Error → record_failure()
    │         │
    │         └──→ Health store: failures=2, cooldown=10s
    │
    ▼
Provider B (KBS) ← failover
    │
    └──→ Request → Success → record_success()
```

## 6. Quyết định kiến trúc

| Quyết định | Lý do |
|:--|:--|
| Two-tier architecture | Tách biệt dữ liệu ẩn danh và cá nhân hóa |
| Health-based routing | Tự động chọn provider ổn định |
| Connection pool | Tái sử dụng TCP connection, giảm TLS handshake |
| Normalizer tập trung | Đảm bảo schema nhất quán |
| Auth providers auto-detect | Giảm cấu hình cho người dùng |
