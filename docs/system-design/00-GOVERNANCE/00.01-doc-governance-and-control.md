## 1. Mục đích & phạm vi

### 1.1 Mục đích

Tài liệu này tồn tại để **chặn sai lệch giữa tài liệu và codebase**. Mọi tài liệu kỹ thuật
trong `docs/system-design/` là **configuration item** có chủ sở hữu, chu kỳ rà soát và
quy trình kiểm soát thay đổi.

Ba mục tiêu cụ thể:

| # | Mục tiêu | Chỉ số đo |
|:--|:--|:--|
| G1 | Tài liệu định lượng không bao giờ lạc hậu | Script `gen-inventory.py --check` exit 0 |
| G2 | Mọi khẳng định kiến trúc truy vết được tới mã nguồn | Tỉ lệ khẳng định không kèm `file:line` |
| G3 | Đồng bộ tài liệu ↔ code base | Quy trình trong `00.03-doc-sync-policy.md` |

### 1.2 Phạm vi

**Trong phạm vi:**
- Toàn bộ `docs/system-design/`
- Mọi thay đổi kiến trúc trong `vnbroker/`
- Quy trình phát triển trong `11-DEVELOPMENT/`

**Ngoài phạm vi:**
- Tài liệu lịch sử trong `docs/*.md` (không còn maintain)
- Code trong `vnbroker/` (chỉ tham chiếu, không sửa)

## 2. Quy ước mức độ tin cậy

| Ký hiệu | Nghĩa | Yêu cầu khi sử dụng |
|:--|:--|:--|
| ✅ **XÁC MINH** | Đã đọc code, đã chạy lệnh kiểm chứng | Có thể dùng làm căn cứ quyết định |
| ⚠ **SUY LUẬN** | Suy từ bằng chứng gián tiếp | Phải nêu rõ cơ sở suy luận |
| ❓ **CHƯA XÁC MINH** | Chưa đọc được hoặc chưa có bằng chứng | **Không được dùng làm căn cứ quyết định** |

---

## 3. Quy trình kiểm soát thay đổi

### 3.1 Thay đổi tài liệu

1. **Đề xuất:** Mở PR với thay đổi tài liệu
2. **Rà soát:** Tech Lead kiểm tra tính chính xác, truy vết `file:line`
3. **Phê duyệt:** Merge chỉ khi tất cả khẳng định đều ✅ XÁC MINH
4. **Cập nhật:** Chạy script `gen-inventory.py` để cập nhật số liệu

### 3.2 Thay đổi code ảnh hưởng tài liệu

1. **Xác định tác động:** Thay đổi code nào ảnh hưởng tài liệu nào
2. **Cập nhật tài liệu:** Sửa tài liệu TRƯỚC khi merge code
3. **Kiểm chứng:** Chạy test + script inventory
4. **Đồng bộ:** Commit tài liệu và code cùng nhánh
